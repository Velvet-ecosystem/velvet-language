# Developmental Language Architecture

## Purpose

Velvet Language should improve through accumulated, verified experience without collapsing language learning, cognition, memory, and authority into one subsystem.

The goal is not to imitate childhood. The useful engineering analogy is developmental competence: begin with bounded expression, retain experience, generalize reusable patterns, accept correction as evidence, and become more fluent over time while preserving hard safety and truth boundaries.

## Ownership

### `velvet-language`

Owns:

- lexical associations
- sentence frames and grammar realization
- phrase preference
- language-specific confidence
- conversational expression outcomes
- language experience objects
- selection of approved learned expressions

Does not own:

- canonical memory admission
- unrestricted learning policy
- self-modification authority
- protected-domain changes
- identity
- actuation or runtime authority

### `velvet-ai-core`

Owns or coordinates governed learning, reflection, prediction/outcome evidence, and plasticity boundaries.

Language-specific adaptation should integrate with Core rather than inventing a second independent learning system.

## Development Loop

```text
verified world meaning
        |
        v
language realization
        |
        v
utterance / text
        |
        v
human response + system outcome
        |
        v
language experience observation
        |
        v
governed learning evaluation
        |
        v
approved language association / pattern
        |
        +---------------------> future realization
```

## Language Experience Object

A language experience object records evidence. It does not apply a permanent change by itself.

Example:

```yaml
experience_id: lang-exp-001
kind: correction
concept: engine.combustion_instability
observed_expression: running_irregularly
candidate_expression: sputtering
source_role: owner
context:
  domain: vehicle
  subsystem: engine
confidence: 0.91
evidence_refs:
  - event-123
  - receipt-456
proposal_only: true
change_applied: false
```

## Learnable Categories

Initial learnable categories should remain low-risk:

- synonyms
- preferred owner terminology
- domain-specific vocabulary
- sentence-frame preference
- verbosity preference by context
- acknowledgement style
- noncritical phrasing preference
- common comparison language

These are not equivalent to authority, safety, identity, medical policy, or emergency language.

## Protected Categories

The following should not be altered by ordinary language experience:

- emergency commands and warnings
- medical critical terminology
- authority and permission language
- authentication language
- Court or capability claims
- identity statements
- receipt claims
- safety thresholds
- actuation claims
- uncertainty guarantees

## Reinforcement

One successful phrase use should not automatically become permanent language policy.

Useful evidence may include:

- direct owner correction
- repeated owner usage
- repeated successful comprehension
- reduced clarification requests
- stable domain association
- cross-context confirmation
- lack of contradiction over time

Reinforcement should increase confidence in a language association, not manufacture confidence in the underlying world fact.

## Generalization

Velvet should prefer learning reusable semantic structures over memorizing isolated sentences.

Example source experiences:

```text
The engine is sputtering a bit.
The LAN is lagging a bit.
The fan is vibrating a bit.
```

Possible generalized frame:

```text
The {subject} is {condition} a bit.
```

The frame is reusable only when every required slot is supplied by verified meaning.

## Maturity

Language maturity should describe capability, not age or intelligence.

Possible dimensions:

- vocabulary breadth
- frame coverage
- correction history
- successful realization rate
- clarification rate
- repetition rate
- contextual phrase selection
- domain-specific terminology confidence

Maturity metrics must not become authority metrics.

## Model Independence

A generative model may be used as an optional assistant for permitted novel expression. It must not own language history, permanent vocabulary, language policy, or the only path to fluent conversation.

The long-term target is that Velvet can conduct the majority of ordinary embodied conversation from her own accumulated language competence, world understanding, memory, and experience.
